00任務與策略

所有設計都從評分標準推導出來：速度分數最高 65 分，比吸力的 32 分還重要，所以要追求「路線短、行為穩定」。

評分項目（期末自走）分數對設計的意義
速度：2:30 內離場65最重要。路線要短，不做探索
吸力：正分紙片共 80 張32至少要吸 30 張，否則時間分數 ×0.8
辨識：進入辨識區並做出反應+10 / −10完全沒進辨識區會倒扣
中央綠色紙片沒吸到−10一定要開到場地正中央
右上紅色紙片−0.5/張經過時要暫停吸塵
撞牆、人工調整−1、−2/次行為要穩定可重複
限制

不能裝輪子編碼器，也不能另外加感測器。我們手上只有課程提供的 MPU6050（IMU）、兩顆 HC-SR04 超音波，加上攝影機。

策略：場地是四面有牆的方框，紙片的位置固定，所以把牆壁當成尺。車子只走平行牆壁的直線，用超音波量到牆的距離判斷自己在哪裡，用陀螺儀維持方向。詳細做法見第 03 節。

Block diagram

01系統方塊圖

Pi 負責「想」：影像、決策、通訊。Arduino 負責「即時控制」：準時讀感測器、輸出 PWM。兩邊只靠一條序列埠溝通。

為什麼要分兩顆腦

Raspberry Pi 4

  • 跑 Linux，可以處理影像、跑 ROS2、開 Wi-Fi 串流
  • 缺點：Linux 不保證「準時」，偶爾會延遲幾十毫秒
  • GPIO 是 3.3V，直接接 5V 的 HC-SR04 會燒壞

Arduino Uno

  • 沒有作業系統，迴圈每次都準時執行，適合積分陀螺儀、量測超音波回波時間
  • 5V 邏輯，可以直接接 HC-SR04 和 L298N
  • 缺點：記憶體只有 2KB，不能做影像處理
分工好處

兩邊只靠「序列埠協定」溝通（第 05 節）。負責 Arduino 的組員完全不需要學 ROS2，只要照協定收發文字就好。

Power

02電源架構

馬達啟動時電流很大，會讓電壓瞬間下降。如果 Pi 和馬達共用同一路電，Pi 可能會當機重開，所以電源要分成三路。

待確認

課程提供的鋰電池規格（幾顆、幾伏特、容量）。8 分鐘比賽加上前後測試，Pi 4 約 3–5W、馬達和風扇另計，需要估算電池撐不撐得住。

Localization without encoders

03無編碼器定位：用牆壁當尺

一般機器人用輪子編碼器算「走了幾圈」。我們不能裝，所以改成直接量「離牆多遠」。

要知道什麼用什麼怎麼做
方向 θMPU6050 陀螺儀 z 軸開機時靜止 2 秒，估計零點偏移；之後把角速度積分成角度。用來走直線、轉精準的 90°
前進到哪裡前方 HC-SR04只走平行牆壁的直線，用「離前牆多遠」當停止條件，例如「朝東走，直到前方 = 150cm」
離側牆多遠右側 HC-SR04沿牆走時維持固定距離
修正陀螺儀漂移右側 HC-SR04沿牆走時，如果側邊距離慢慢變大，代表車頭往外偏，可以反推角度誤差並拉回來
名詞

漂移（drift）：陀螺儀量的是「轉多快」，要一直累加才會得到「轉了幾度」。小誤差累加久了會越來越大，像是時鐘每天慢一點點，一個月後就差很多。校正好的 MPU6050 在 8 分鐘內大約會飄幾度。

我們考慮過、但沒有採用的方法

方法原理為什麼不用
VIO（視覺慣性里程計）攝影機追蹤畫面中的特徵點，搭配 IMU 推算位移場地是素面地板＋素面牆，特徵點太少；C310 是捲簾快門，暗處只有約 13 fps；Pi 4 算力不足
SLAM＋Nav2邊建地圖邊定位，再用導航框架規劃路徑需要光達或輪子里程計，我們都沒有；在這個簡單場地是殺雞用牛刀
只靠時間盲走「全速走 3 秒 ≈ 60cm」電池電壓一降、地板一滑就不準，沒有任何回饋

04路線與流程

路線是順時針繞場，讓牆壁大多在右手邊，右側超音波才量得到。每一段都只有一個停止條件。

#動作停止條件（前方超音波）經過
1從入口朝東前進前方 = 278cm（x ≈ 22）
2右轉朝南前方 = 22cmBL 紙片區
3左轉朝東前方 = 22cmBR 紙片區
4左轉朝北前方 ≈ 70cm停在右上扣分區下方
5左轉朝西前方 = 22cm
6右轉朝北前方 = 22cmTL 紙片區
7掉頭朝南前方 = 150cm
8左轉朝東前方 = 150cm中央綠色紙片
9掉頭朝西，出場前方 ≈ 10cm出口

總長約 12m。TT 馬達如果跑 20–25 cm/s，再加上轉彎時間，大約 1.5–2 分鐘，有機會拿到 2:30 以內的滿分。實際數值要扣掉感測器到車體中心的距離，等車體確定後再調整。

右上角 進入扣分區之前→ 關掉吸塵風扇→ 離開後再打開

05Arduino 韌體與序列埠協定

這是 Pi 和 Arduino 之間的「合約」。只要雙方都照這個格式收發，兩邊就可以分開開發、分開測試。

Pi → Uno（指令）

V <線速度> <角速度>   # 移動，-255~255
S                      # 停車
F <0|1>                # 吸塵風扇
B <0|1>                # 蜂鳴器
Z                      # 航向角歸零

Uno → Pi（每秒 50 次）

D <yaw°> <前cm> <右cm>
# 例：D 90.4 148.2 23.0
L <文字>
# debug 訊息

Uno 迴圈要做的事

工作頻率說明
讀 MPU6050、積分 yaw200 Hz頻率越穩，積分越準
觸發超音波各約 15 Hz兩顆輪流觸發，避免收到對方的回波
航向 PID200 Hz在 Uno 上做，反應最快；Pi 只給目標
回報資料給 Pi50 HzD 開頭那行
安全停車—300ms 沒收到 Pi 的指令就自動停車（斷線保護）

接腳（暫定）

元件Uno 腳位
MPU6050 SDA / SCLA4 / A5
HC-SR04 前 Trig / EchoD2 / D3
HC-SR04 右 Trig / EchoD4 / D7
L298N ENA / ENB（PWM）D5 / D6
L298N IN1–IN4D8 / D9 / D10 / D11
蜂鳴器D12
繼電器（風扇）D13
注意

Uno 只有一組硬體序列埠，而且已經接給 Pi 使用，所以 Serial.print 的 debug 訊息一定要用 L 開頭，Pi 才分得出哪些是資料、哪些是訊息。

06影像串流（已完成）

期中要「看著串流遙控」，比賽現場網路可能很差，所以串流的目標是低延遲、低頻寬、斷線能自己恢復。

~1 Mbps頻寬，約為 MJPEG 的 1/5～1/10
15–20%Pi 4 CPU（硬體 H.264 編碼）
0.5 s關鍵幀間隔，掉封包後的恢復時間
3 s畫面停止多久後，看門狗自動重啟攝影機
設計原因
WebRTC（UDP）掉封包時直接跳過，延遲不會越積越多；UDP 被擋時自動改走 TCP
不依賴網際網路現場沒有外網也能用；我們會自帶路由器，讓筆電和 Pi 直接連線
同學原本的 cv2.imshow 方案只會顯示在 Pi 自己的螢幕上；改用 SSH 轉發要傳未壓縮畫面（約 70 Mbps），所以不採用

ROS2 in five minutes

07ROS2 是什麼

ROS2（Robot Operating System 2）不是作業系統，而是一套讓「很多支小程式互相傳訊息」的框架，幾乎所有研究用機器人都在用。

可以把它想成一間公司：

ROS2 名詞比喻在我們的車上
Node（節點）一位員工，只負責一件事vision 只負責找紅色圓形
Topic（主題）一個公告頻道，有名字/range/front 頻道專門放前方距離
Message（訊息）固定格式的表單sensor_msgs/Range：距離、量測範圍、時間戳記
Publish（發布）往頻道貼公告arduino_bridge 每秒貼 50 次距離
Subscribe（訂閱）訂閱頻道，有新公告就通知我localizer 訂閱距離來算位置

重點是：發布的人不需要知道誰在聽，訂閱的人也不需要知道誰在發。大家只要約定好頻道名稱和表單格式。

實際的程式長怎樣

發布端（arduino_bridge 的一部分）：

from sensor_msgs.msg import Range

class Bridge(Node):
    def __init__(self):
        super().__init__('arduino_bridge')
        self.pub = self.create_publisher(Range, '/range/front', 10)

    def on_serial_line(self, front_cm):      # 每收到一行 "D ..." 就呼叫
        msg = Range()
        msg.range = front_cm / 100.0            # ROS 一律用公尺
        self.pub.publish(msg)

訂閱端（mission 的一部分）：

self.create_subscription(Range, '/range/front', self.on_front, 10)

def on_front(self, msg):
    if msg.range <= self.target:           # 到達這一段的停止條件
        self.next_leg()

好用的指令

指令用途
ros2 topic list列出現在有哪些頻道
ros2 topic echo /range/front即時看前方距離（不用寫任何程式）
ros2 topic pub /cmd_vel ...手動送一個移動指令，測試馬達
rqt_graph畫出所有 node 和 topic 的連線圖
ros2 bag record -a把所有頻道的資料錄下來，回家可以重播、調參數
Why ROS2

08為什麼用 ROS2？不用會怎樣？

不用 ROS2 也做得出來，但所有功能會擠在同一支大程式裡。專案越長越大，就越難分工和除錯。

不用 ROS2：一支大程式

  • 讀序列埠、影像辨識、決策、網頁遙控全寫在一起，要自己處理多執行緒
  • 影像辨識當掉，整台車跟著停
  • 四個人改同一個檔案，Git 一直衝突
  • 想看「現在前方距離是多少」，要自己加 print
  • 練習時出錯，只能重跑一次，祈禱問題再出現
  • 期中遙控和期末自走大概要寫成兩支程式

用 ROS2：很多個小 node

  • 每個 node 只做一件事，每個人負責自己的 node
  • 每個 node 是獨立的程式，一個當掉不影響其他
  • 每個 node 可以單獨測試：用 ros2 topic pub 假裝別人送資料進來
  • ros2 topic echo、rqt_graph 直接看資料流
  • ros2 bag 錄下練習時的感測資料，回家重播、調參數
  • 期中換期末，只要把 web_teleop 換成 mission，其他不用動

ROS2 的代價，以及我們怎麼降低

代價對策
要學新東西，組員大多不熟只有 Pi 端用 ROS2；Arduino 端完全不需要。每個 node 都很小，照範本改就好
安裝和設定比較麻煩由熟的人在 Pi 上裝好，大家用同一套環境
多佔一些 Pi 的資源Node 數量控制在 6 個左右；影像串流不走 ROS2，直接用 MediaMTX
Nav2、SLAM 等現成套件用不上我們只用 ROS2 的「溝通框架」和「工具」，不依賴這些大型套件

Interface to mechanical design

10電控對機構組的需求

機構由其他組員發想。下面是電控這邊需要機構配合的地方，設計車體時請一起考慮。

項目需求原因
前方超音波車頭正中央、朝正前方、離地約 5–15cm，前面不能有東西擋住牆高 30–40cm；超音波的波束約 30°，太低會打到地板
右側超音波車身右側中間、垂直朝右沿牆時要量到側牆的距離
MPU6050靠近兩輪中間（旋轉中心）、水平、鎖緊不能晃晃動和風扇的震動會變成雜訊
攝影機車頭偏高處、略微朝下，角度可以調整要看到前方地面，也要看到角落離地的紅色圓形標的
電子元件空間Pi 4、Uno、L298N、降壓模組、電池、繼電器上層放 Pi 和 Uno，方便插拔線
車體尺寸建議 ≤ 20cm紙片區離牆只有 15cm，車太大轉角會撞牆
吸塵風扇和 IMU 之間盡量做隔震同上，減少陀螺儀雜訊

Difficulties

12可能遇到的困難與對策

困難影響對策
沒有編碼器，不知道走了多遠自走時定位不準用超音波量牆距；只走平行牆壁的直線
陀螺儀漂移方向慢慢偏掉開機時校正零點；沿牆走時用側邊距離修正
超音波斜射時量不到、兩顆互相干擾距離讀值亂跳盡量垂直對牆；兩顆輪流觸發；用中位數濾波
比賽現場網路差串流延遲、畫面卡住硬體 H.264＋WebRTC；自帶路由器
馬達啟動時電壓下降Pi 當機重開電源分三路、加電容、共地
吸力不足、紙片卡在吸口吸不到 30 張提早做吸力測試，調整吸口高度
攝影機只能被一支程式打開串流和辨識搶攝影機由 camera node 統一讀取再分送
組員大多不熟 ROS2軟體進度卡住Arduino 端不需要 ROS2；每個 node 都很小，可以照範本改
