## 01 Mechanical Design（機構設計）

📘 吸塵器的原理：風扇把空氣往外打，集塵盒裡的氣壓變低，紙片就從吸口被吸進來。所以吸力取決於**風扇的風量和風壓**，以及**吸口離地多高、有多寬**。

### 1-1 車體總覽
- 內容：整台車的 3D 圖或手繪圖，標出每個零件的位置
  - 兩輪差速＋萬向輪（📘 左右輪轉速不同就能轉彎，不需要轉向機構）
  - 車體尺寸（待定，建議 ≤ 20cm 以便進出角落）
  - 上下層配置：下層放馬達、電池、吸塵；上層放 Pi、Arduino、攝影機
- 加工方式：底盤用雷射切割（壓克力/密集板），曲面零件用 3D 列印
- ❓ 待決定：車體尺寸、形狀（圓形比較不會卡牆角，方形比較好吸角落）

### 1-2 Fan Design（風扇）
- 內容：風扇型式、馬達、預估風量，附上設計圖
- 選項比較表：

| 選項 | 優點 | 缺點 |
|---|---|---|
| 3D 列印離心葉輪＋課程提供的直流馬達 | 可以自己設計、有報告亮點 | 要反覆測試 |
| 現成的鼓風扇（blower） | 穩定 | 要另外買，比較耗電 |

- ❓ 待決定：選哪一種、怎麼量測吸力（例如：能吸起幾公分外的紙片）

### 1-3 Suction Inlet（吸口）
- 內容：位置、寬度、形狀、離地高度
- 設計依據：紙片區 15×15cm → 吸口寬度最好能一次掃過大部分紙片區
- 圖：吸口的剖面圖（標出離地高度）
- ❓ 待決定：放在車頭（好對準）還是車身中間（重心比較穩）

### 1-4 Brush（刷子）
- 內容：要不要加邊刷（📘 車子兩側旋轉的刷子，可以把紙片掃進吸口，讓吸塵範圍變寬）
- ❓ 待決定：要不要加刷子？加的話需要多一顆馬達

### 1-5 Weight & Deflection Validation（重量與變形驗證）
- 內容：
  - 重量估算表：每個零件的重量加總，算出總重和重心位置
  - 底板受力的變形估算（📘 把底板當成簡支樑，用材料力學的撓度公式，確認板子不會被壓彎到讓吸口刮地）
- ❓ 待決定：底板材料和厚度

## 02 Electrical Design（電控設計）

### 2-1 系統方塊圖（Block Diagram）⭐ 最重要的一頁
- 內容：所有電子元件和它們之間的連線，**每條線都標出通訊方式**
- 圖：分成三層
  - 上層：筆電／手機 ←WebRTC (Wi-Fi)→ Raspberry Pi 4 ←USB→ C310 攝影機
  - 中層：Pi 4 ←UART→ Arduino Uno
  - 下層：Uno →PWM→ L298N → TT 馬達 ×2；Uno ←I²C← MPU6050；Uno ←GPIO← HC-SR04 ×2；Uno → 繼電器 → 風扇；Uno → 蜂鳴器
- 📘 分工的理由：Pi 擅長「想」（影像、決策），Arduino 擅長「即時控制」（準時讀感測器、輸出 PWM）
- 工具：draw.io

### 2-2 電源架構
- 內容：電池 → 降壓模組 → Pi（5V 3A）；電池 → L298N → 馬達；電池 → 繼電器 → 風扇
- 📘 為什麼要分開：馬達啟動時電流很大，會讓電壓瞬間掉下去，如果和 Pi 共用同一路電，Pi 可能會當機重開
- ❓ 待決定：電池規格（課程提供的鋰電池是幾顆、幾伏特）、要不要加電壓偵測

### 2-3 Software 架構
- 內容：ROS2 Node 圖（📘 ROS2 是機器人用的軟體框架，把程式拆成很多小模組（node），模組之間透過 topic 傳訊息）
  - arduino_bridge、localizer、mission、vision、web_teleop
- 期中和期末共用同一套架構：期中由 web_teleop 下指令，期末換成 mission 下指令
- 串流：MediaMTX＋硬體 H.264＋WebRTC（已完成，可以放實測數據：CPU 15–20%、約 1 Mbps）

### 2-4 Flow Chart（流程圖）
- 期中：遠端遙控流程（網頁按鍵 → Pi → Arduino → 馬達；攝影機 → 串流 → 網頁）
- 期末：自走任務狀態機（出發 → BL → BR → 繞過右上 → TL → 中間 → 出口，沿途偵測辨識標的）
- 圖：狀態機圖＋場地路線圖並排

### 2-5 定位方法（Others）⭐ 報告亮點
- 內容：沒有編碼器要怎麼知道自己在哪裡？
  - 方向：MPU6050 陀螺儀積分
  - 位置：前方超音波量到前牆的距離、右側超音波量到側牆的距離
  - 修正：沿牆走時，用側邊距離的變化修正陀螺儀漂移
- 可以附上「為什麼不用 VIO/SLAM」的比較（展現有做研究）

## 05 Difficulties（可能遇到的困難）

| 困難 | 影響 | 對策 |
|---|---|---|
| 沒有編碼器，無法知道走了多遠 | 自走定位不準 | 用超音波量牆距＋陀螺儀；只走平行牆壁的直線 |
| 陀螺儀漂移 | 方向慢慢偏掉 | 開機時校正偏移；沿牆走時用側邊距離修正 |
| 超音波斜射到牆面會量不到；兩顆會互相干擾 | 距離讀值跳動 | 盡量垂直對牆；兩顆輪流觸發；中位數濾波 |
| 比賽現場網路差 | 串流延遲、畫面卡住 | 硬體 H.264＋WebRTC；自備路由器 |
| 馬達啟動時電壓下降 | Pi 當機重開 | 電源分開、加電容 |
| 吸力不足、紙片卡在吸口 | 吸不到 30 張 | 提早做吸力測試，調整吸口高度 |
| 組員大多不熟 ROS2 | 進度卡在軟體 | Arduino 端不需要 ROS2；用序列埠協定把工作切開 |
