## 1. 腳位改成 Arduino Nano

MCU 從 STM32 Nucleo-L432KC 換成 Arduino Nano（ATmega328P，FT232R USB 轉序列，`/dev/ttyUSB0`）。
Nucleo 的程式還保留，`./build.sh -e nucleo_l432kc` 照樣可以編。

洞洞板焊好後的實際接線（`firmware/src/config.h`）：

| 功能 | Nano 腳位 | 備註 |
|---|---|---|
| PWMA（左馬達） | D6 | Timer0 硬體 PWM，976Hz |
| PWMB（右馬達） | D7 | **沒有硬體 PWM**，改用 Timer1 中斷模擬（976Hz），所以 D9/D10 不能再當 PWM |
| AIN1 / AIN2 | A3 / A2 | |
| BIN1 / BIN2 | A1 / A0 | |
| STBY | 3.3V | 常駐致能，停車靠 PWM = 0 |
| MPU6050 SDA / SCL | A4 / A5 | |
| 空腳 | D2–D5、D8–D12 | 留給超音波、蜂鳴器、吸塵器 |

順便加的韌體功能：

- **加減速限制**：`V` 指令只設定目標，輸出每 300ms 最多從 0 變到 255。可以用 `A <ms>` 即時調整（`A 0` = 不限制）。`S` 和逾時停車還是立刻停。
- **IMU 容錯**：偶發的 I²C 讀取失敗直接跳過那一筆，連續失敗 10 次才當作 IMU 斷線。重新初始化時保留 bias 和 yaw。
- `Wire.setWireTimeout`：I²C 線鬆掉不會卡死整個 loop。
- `R` 指令用 watchdog 重開機。
- 網頁、bridge、README 裡的 STM32 字樣都改成 Nano。

## 2. IMU + 馬達測試

新增 `firmware/imu_motor_test.sh [speed]`：輪子懸空，依序跑「靜止 → 前進 → 瞬間反轉 → 原地左轉 → 原地右轉 → 停車」。
先用 `A 0`（不限制加減速）跑一次，再用 `A 300` 跑一次，統計陀螺儀雜訊、yaw 漂移和 I²C 錯誤。

**第一次（下午，速度 255，Pi 接 USB-C 充電器，馬達沒有電容）**

- `A 0`：反轉瞬間陀螺儀尖峰到 14°/s
- `A 300`：最大 0.85°/s，漂移 < 0.1°
- 馬達轉動時大約 6–7% 的 I²C 讀取失敗（靜止時 0）→ 有刷馬達的電磁干擾

**第二次（晚上，速度 120，全部 18650 供電，馬達焊了電容）**

| | 漂移 | 最大 \|rate\| | I²C 錯誤 | IMU 斷線 |
|---|---|---|---|---|
| `A 0` | −0.16° | 3.67°/s（前進起步） | 0 | 0 |
| `A 300` | 0.02° | 0.17°/s | 0 | 0 |

測完 `get_throttled` = 0（沒有欠壓），Pi 也沒有重開。

**結論**

- 加減速限制有用。`A 300` 的數字跟靜止時一樣，維持預設 300ms。
- I²C 錯誤從 6–7% 變成 0。不過這次速度只有 120，電源也換了，所以**不能確定是電容的功勞**。要公平比較，得在速度 255 再跑一次。

## 3. Pi 當機和供電

- 18:28 馬達焊完電容後，**Pi 直接斷電重開**（journal 直接中斷，沒有正常關機）。當時沒有程式在送馬達指令。
- 懷疑的原因：Nano 插著 USB 時熱插拔電池產生突波、焊錫橋接、焊接時 USB 沒拔、充電器電力不足。
- 改成 Pi 和其他東西**全部用 18650 供電**，之後的測試都很穩定。
